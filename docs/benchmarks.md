# Query benchmarks (PROFILE before / after)

Generated by `make benchmark` (`scripts/benchmark.py`) on Neo4j 5.26.32 community, local Docker. Latency is the median of 7 runs after 2 warm-ups, measured from the client. Every pair is checked to return the same result.

| Case | Change | db hits before | db hits after | gain | ms before | ms after |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| Exact name lookup | Range index on Player.name instead of scanning every Player | 4,634 | 3 | 1,545x | 3.5 | 2.3 |
| Name search (substring) (see note) | Full-text index with accent folding instead of toLower/CONTAINS on every Player | 4,634 | 1 | 4,634x | 5.6 | 4.1 |
| Matches in one week | Range index on Match.date instead of scanning all 102k matches | 204,837 | 130 | 1,576x | 35.0 | 2.5 |
| Career totals | Conditional counts in one subquery instead of chained OPTIONAL MATCH (rows multiply: wins x losses) | 982,848 | 7,434 | 132x | 181.4 | 7.4 |
| Nemesis top 10 | Read the derived BEAT edge instead of aggregating matches | 2,867 | 460 | 6x | 3.8 | 3.1 |
| Beat cycles through a player | 3-cycle over BEAT instead of over Match nodes (6 hops, no aggregation before the join) | 71,166,129 | 23,430 | 3,037x | 9,112.1 | 6.7 |
| Beat chain (3 hops) | SHORTEST over BEAT instead of a quantified path over Player-Match-Player | 334,690 | 365 | 917x | 118.5 | 3.0 |

## Investigated without gain

- **Match history page (Federer, 20 per page).** Cutting the page before the tournament, opponent and odds lookups did not reduce work: the planner already avoids it. Same-field 'lookups then ORDER BY/SKIP/LIMIT': 6,542 db hits, 14.5 ms; page first: 6,542 db hits, 9.4 ms, plus a separate count query (3,000 db hits, 4.5 ms) for the total. The API keeps one query that returns page and total together (8,237 db hits, 15.0 ms): one round trip, same latency.

## Plans

### Exact name lookup

- Before: NodeByLabelScan
- After: NodeIndexSeek

```cypher
// before
MATCH (p:Player) USING SCAN p:Player WHERE p.name = $name RETURN p.id AS id
// after
MATCH (p:Player) WHERE p.name = $name RETURN p.id AS id
```

### Name search (substring)

- Before: NodeByLabelScan, Sort
- After: ProcedureCall, Sort
- Note: db hits do not count the work done inside the full-text procedure (Lucene). With 2,316 players a scan is cheap, and latency is about equal; the index is chosen for accent folding and word-prefix matching, and because a scan grows with the number of players.

```cypher
// before
MATCH (p:Player) WHERE toLower(p.name) CONTAINS $text RETURN p.id AS id ORDER BY id
// after
CALL db.index.fulltext.queryNodes('player_name_ft', $query) YIELD node RETURN node.id AS id ORDER BY id
```

### Matches in one week

- Before: EagerAggregation, NodeByLabelScan
- After: EagerAggregation, NodeIndexSeekByRange

```cypher
// before
MATCH (m:Match) USING SCAN m:Match WHERE m.date >= date($since) AND m.date <= date($until) RETURN count(m) AS n
// after
MATCH (m:Match) WHERE m.date >= date($since) AND m.date <= date($until) RETURN count(m) AS n
```

### Career totals

- Before: EagerAggregation, NodeUniqueIndexSeek, OptionalExpand(All)
- After: EagerAggregation, Expand(All), NodeUniqueIndexSeek

```cypher
// before
MATCH (p:Player {id: $id}) OPTIONAL MATCH (p)-[:WON]->(w:Match) WHERE NOT w.walkover OPTIONAL MATCH (p)-[:LOST]->(l:Match) WHERE NOT l.walkover RETURN count(DISTINCT w) AS wins, count(DISTINCT l) AS losses
// after
MATCH (p:Player {id: $id}) CALL (p) { MATCH (p)-[r:WON|LOST]->(m:Match) WHERE NOT m.walkover RETURN count(CASE WHEN type(r) = 'WON' THEN 1 END) AS wins, count(CASE WHEN type(r) = 'LOST' THEN 1 END) AS losses } RETURN wins, losses
```

### Nemesis top 10

- Before: EagerAggregation, Expand(All), NodeUniqueIndexSeek, Top
- After: Expand(All), NodeUniqueIndexSeek, Top

```cypher
// before
MATCH (p:Player {id: $id})-[:LOST]->(m:Match)<-[:WON]-(o:Player) WHERE NOT m.walkover WITH o, count(m) AS wins ORDER BY wins DESC, o.name LIMIT 10 RETURN o.id AS id, wins
// after
MATCH (p:Player {id: $id})<-[b:BEAT]-(o:Player) WITH o, b.wins AS wins ORDER BY wins DESC, o.name LIMIT 10 RETURN o.id AS id, wins
```

### Beat cycles through a player

- Before: EagerAggregation, Expand(All), Expand(Into), NodeUniqueIndexSeek
- After: EagerAggregation, Expand(All), NodeUniqueIndexSeek

```cypher
// before
MATCH (a:Player {id: $id})-[:WON]->(m1:Match)<-[:LOST]-(b:Player) WHERE NOT m1.walkover WITH DISTINCT a, b MATCH (b)-[:WON]->(m2:Match)<-[:LOST]-(c:Player) WHERE NOT m2.walkover AND c <> a WITH DISTINCT a, b, c WHERE EXISTS { (c)-[:WON]->(m3:Match)<-[:LOST]-(a) WHERE NOT m3.walkover } RETURN count(*) AS cycles
// after
MATCH (a:Player {id: $id})-[:BEAT]->(b:Player)-[:BEAT]->(c:Player)-[:BEAT]->(a) WHERE b <> c RETURN count(*) AS cycles
```

### Beat chain (3 hops)

- Before: CartesianProduct, NodeUniqueIndexSeek, StatefulShortestPath(Into)
- After: CartesianProduct, NodeUniqueIndexSeek

```cypher
// before
MATCH (s:Player {id: $source}) MATCH (t:Player {id: $target}) MATCH p = SHORTEST 1 (s) ((x:Player)-[:WON]->(m:Match)<-[:LOST]-(y:Player) WHERE NOT m.walkover){1,6} (t) RETURN length(p) / 2 AS hops
// after
MATCH (s:Player {id: $source}) MATCH (t:Player {id: $target}) MATCH p = SHORTEST 1 (s)-[:BEAT]->{1,6}(t) RETURN length(p) AS hops
```
